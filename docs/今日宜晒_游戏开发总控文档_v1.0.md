>
> 基于 Claude 的《今日宜晒》原创小游戏设计案 v0.1 扩写、梳理与修正。原有定位、二十四节气世界观、天气—摆放—抢收核心、晒物与街坊、数据驱动运营路线均保留；本文所有【调整】均为新决策，不应误认为原案内容。

## 0. 这款游戏最终要做成什么

- 暂定名：《今日宜晒》。广告为主要商业化方式，**不是**以广告观看为核心玩法。
- 平台顺序：**可直接浏览器试玩的 H5 核心原型 → 真机体验与数据验证 → 微信小游戏工程移植 → 平台资质/广告接入/上线**。H5 原型本身不等于合规可上架的微信小游戏。
- 目标用户：喜欢可爱国风、2–3 分钟轻策略、治愈收集的微信用户；用单手可操作、首关免看教程解释，降低门槛。
- 卖点：**一院子会变天的晒物**；不同晒物晒法不同、刚好收回才最值钱。雨前抢收让人紧张；收成金光和小院变美带来满足。
- 体验承诺：**10 秒能学会“放进去”，60 秒体验一次“抢收”，3 分钟完成完整一局。** 为设计目标，必须实测。
- 不做：复杂战斗、自动挂机、强制广告、广告买分、公平榜付费强化、纯按钮经营、大量首屏入口。

### 0.1 核心一句话

> 把吃食放进竹匾，看天气、找好位置、抢在下雨或晒过头之前收回来，把小院一点点晒成四季的模样。

### 0.2 三条产品检验线（未经验证，不写“留存高”）

1. **看得懂**：第一次进入 10 秒内能正确拖入第一件晒物；15 人可用性测试中至少 12 人无需口头指导完成。
2. **玩得爽**：一局至少出现 2 次清晰的收成/转折反馈；试玩 10 人中至少 6 人自愿开第二局（仅作为筛选阈值，不是留存率）。
3. **愿意回来**：正式埋点后看 D1/D7 留存与每日自然局数；起步观察目标 D1≥25%、D7≥7%，只是待验证的内部假设，不是行业基准或收益预测。

## 2. 玩家能看见的游玩循环

### 2.1 前60秒：必须有动作，而不是读说明

- **0–5 秒**：打开就是会呼吸的小院；一篮萝卜干在底部轻摇；屏幕中央一句话「把萝卜拖到阳光里」。没有登录、无商城弹窗。
- **5–12 秒**：玩家拖入太阳格；竹匾有弹性落下，小萝卜从微湿变得略卷；触感反馈（设备允许时）和“笃”的竹木声。
- **12–25 秒**：点击「下一时辰」，太阳沿院墙偏移；干度条上涨，在绿区前闪一次柔光。
- **25–40 秒**：天边变暗、雨娃探头，提示「下一时辰可能下雨」；游戏引导玩家点晒物再点「收进屋」。
- **40–55 秒**：雨落，未收的示例晒物被淋湿（教学可以设计成 NPC 的道具，不让新玩家失败）；玩家的萝卜干避开暴雨，金色的“刚刚好”贴纸落在竹匾上。
- **55–60 秒**：弹出极简结算「晒得正好！+20 铜钱」；一键「再晒一天」，金币投进小院装饰进度，不上来就强推广告。

### 2.2 一局六时辰

```
开场天气/当日黄历 → 拖晒物入院 → 调整/遮盖/收进屋（AP=3）
                  ↓
          「日头往前走」推进时辰
                  ↓
           天气结算+可视反馈
                  ↓
      重复六时辰 → 日落品质评价 → 铜钱/星 → 小院成长
```

**速度目标**：有交互的教学局 60–90 秒；普通局 2–3 分钟。用真实录屏测量，不靠估计。

### 2.3 玩法必须产生的取舍

- **位置**：一个好太阳格只能放一匾；快干辣椒还是慢干柿饼先占？
- **时间**：现在就收 = 品质锁住；再晒一步 = 可能进入绿区，也可能过晒或淋雨。
- **工具**：三点行动不够；优先盖怕雨的，还是移走怕暴晒的？
- **天气**：预报不是必然；只有挑战关适度加入预报误差。失败要能从回放中看出原因。
- **搭配**：咸鱼靠近柿饼会串味，不是纯数字，画面要看到一缕气味飘过去。

## 3. 核心数值规则（确定版 v1.0）

> 数值仍为起步值。开发必须使用纯函数和固定测试，改变数值需要更新关卡数据版本，不得偷偷在 UI 里计算。

### 3.1 基本枚举

- 时辰按序 `chen / si / wu / wei / shen / you`，主线固定六回合。
- 天气 `sun / cloud / overcast / wind / rain / fog`，强度分别 `3 / 2 / 1 / 2 / 0 / 1`。
- 场地 `sun / shade / eave / airy / stone`，系数 `1 / 0.5 / 0.5 / 1 / 1`；stone 储热不在 P1 实施，P2 再新增额外结算。
- 晒物状态：`basket` 篮中、`yard` 院中、`inside` 屋内、`spoiled` 报废。收回屋内后停止干度变化，允许花费 AP 再次摆出。
- `cover` = 真时不淋雨、**晒物本回合受光照系数 0**；`pressed` = 真时防大风吹走；转移到屋内可清理盖和压状态。盖/压只能用于院中物品，且每次开启花费 1 AP。取消盖/压 P1 免费单击完成（避免“不够行动点所以无法取消”的卡死）。

### 3.2 本时辰结算顺序（严格）

1. 检查天气、物品状态、所在格和动作合法性。
2. 若雨且物品露天未盖：干度 `max(0, dry−15)`；霉点 +1，若 `rain_fear` 则 +2；霉点≥3 标记 `spoiled`。
3. 若风且有 `light` 标签，物品在露天并未压住且非屋檐：直接 `spoiled`（丢失）。
4. 其它天气：`delta = 4 × sunStrength × cellFactor × dryFactor`；如果 `sun_fear` 且晴且阳光格，乘以 `1.5`；若 `needs_wind`，通风格乘以 `1.3`，其它露天格乘以 `0.7`；雾天露天再 `-3`。遮盖状态不涨干度；屋檐挡雨。结果按 **四舍五入到整数**，限定 0–100。
5. 串味不改变干度，只在最终评价时扣品级；距离定义为正交相邻，不包括对角。P1 若二者任意时辰正交相邻，即记 `smell_hit=true`（一次即可），并在当回合显示可见气味波纹。
6. 所有晒物完成后，更新当前天气效果、反馈动画、进入下一个时辰；第六时辰结算后进入结果。

> **关键解释**：原案例子中的 `4×3×1×1=12`，柿饼为 `4×3×1×0.5=6`；确定天气晴晴晴雨阴晴，提前收入屋内后复晒，萝卜最终52、柿饼26。实现后必须把此例写成回归测试。

### 3.3 品质判定

- 当 `spoiled`、霉点≥3：`霉`，商品得分 0。
- `green=[L,U]`，`dry ∈ [L,U]` 则 `优`；距离绿区边界最短差距 `≤8` 则 `良`；否则 `差`。
- 串味命中则降一级：优→良、良→差、差保持差。
- 商品得分：`优=round(value*1.5)`、`良=value`、`差=round(value*0.5)`、`霉=0`。
- **关卡得分**：商品得分之和，不含保底、广告与经济加成；**铜钱**：`max(5, round(关卡得分))`，普通关的广告可额外增加铜钱，不增加关卡得分。
- **满分线**：按该关所有商品的 `1.5×value` 合计定义，三星比率 `≥0.9`，二星 `≥0.7`，一星 `≥0.4`，否则零星，但照样给保底铜钱。
- 绿区视觉在物品卡内始终可见；玩家可以看到 `52/55–70`，但不会显示数值公式。

### 3.4 天气与公平

- **真实天气**由 `seed + stageId + rulesVersion` 的稳定伪随机算法或固定关卡配置确定，刷新同一关不变。不能用 `Math.random()` 直接产生正式关卡天气。
- **预报天气**由另一个固定 PRNG 从真天气派生，显示下一回合“准”、下两回合“可能”、更远为模糊；90%/70%/50% 是设计目标的**长期命中率**，不是每一局临时重掷结果。
- **前3关**：真实天气及预报均完全固定且准确，只教操作；第4关引入一次预报可能偏差，但提供清晰提示。
- **每日同题模式**：日期需约定 `Asia/Shanghai` 的每日 00:00 切换；内容种子 = 日期 + 关卡版本 + 规则版本；玩家当天相同的地图、物品、预报序列、天气序列、初始 AP、初始工具，不允许升级/广告改变可比条件。
- **回放**：保存种子、操作日志、版本号。挑战榜上报得分必须由服务端或可信校验重新演算；仅本地存档分数不能当防作弊排行榜依据。

### 3.5 五种行动及异常约束

| 行动 | 玩家操作 | AP | 必须拒绝的异常 |
|---|---|---:|---|
| 摆 | 选篮中/屋内物品→点空地 | 1 | 目标不空；物品报废；AP不足 |
| 移 | 点院内物品→点另一空地 | 1 | 目标被占；当前状态非 yard |
| 盖 | 点院内物品→盖罩 | 1 | 已盖、AP不足；盖上时本回合不能晒 |
| 收 | 点院内物品→入屋并锁住干度 | 1 | 不在院中；AP不足 |
| 压 | 点院内物品→放石头 | 1 | 已压、AP不足；P1 只风天相关 |

「收」不是结算/售卖，而是保护成品；第六时辰后自动打包结算，包括仍在院内的完好商品。

## 5. 美术总监规范 —— 主体由 ChatGPT 负责

### 5.1 视觉定位

**风格名：暖绘纸雕 · 小院有晴。** 童书般的温暖感 + 中国乡村院落的生活气息 + 轻微纸雕分层，不追写实，不做廉价扁平拼贴。画面第一眼是**有阳光的小院**，不是一堆浮动面板。以**一院三层**组织：前景竹匾与晾架、中景屋檐与石阶、背景院墙与天空。

原创视觉原则：**不调用其他商业游戏的图标、UI截图、音效或角色当生产素材**；参考仅用于设计方向，不追求“像某游戏”。生产素材须保留创作提示、版本、日期、后期处理记录；AI生成不等于自动具备所有权利或商业授权，发布前另行审查。

### 5.2 色板（HEX）

| 语义 | 名称 | HEX | 用途 |
|---|---|---|---|
| `paper` | 宣纸奶油 | `#F7F0DE` | 面板基础底色 |
| `ivory` | 晨光白 | `#FFFBF1` | 文字卡和高光 |
| `ink` | 松烟墨 | `#3F493F` | 主正文，避免纯黑 |
| `muted` | 苔灰 | `#879184` | 次级说明 |
| `persimmon` | 柿子橙 | `#E8794F` | 主按钮、焦点、刚刚好 |
| `bamboo` | 竹青 | `#5F8F70` | 可互动格、绿区、收获 |
| `sky` | 天青 | `#B9DCE0` | 晴天背景 |
| `rain` | 雨青 | `#6C91B2` | 下雨状态/预警 |
| `gold` | 麦穗金 | `#E3B654` | 成就、星、品质优 |
| `wood` | 木棕 | `#9D7251` | 框架与木制物 |
| `danger` | 霉斑红 | `#B86161` | 失败、异常，不大面积填充 |

**层级要求**：用材质、遮挡、轮廓对比区分前后；全屏同时使用的强调色不超过3种。界面不许全屏渐变卡片堆叠。

### 5.3 核心视觉画面

- **小院**：竖屏中部 **55–63%** 的高度；俯视约35–45° 的微斜角盆景结构，格子点击区域须仍清晰；视觉层与判定层分开。院墙有白灰粉刷、瓦檐、竹影、石阶、风铃，背景可用轻量分层图。支持晴/阴/雨/傍晚色调切换。
- **晒物**：一匾一个主体，道具以形状和颜色即可识别——萝卜条米白长条、柿饼橙圆、辣椒红串、玉米金粒等；至少 **潮湿/适中/过晒/霉变** 四状态；产品图标与场景图必须共享轮廓语言。
- **天气人格化**：阿日（温暖圆太阳，眯眼），云朵团子（软绵绵三瓣云），风婆婆（青色旋风发髻），雨娃（蓝色水滴斗笠）；单个角色具有**一眼可读的剪影**，必须是独立原创形象，不模仿现有知名IP。晴/雨人格动画不得遮挡主要触控区。
- **街坊角色**：首发主引导角色「柿子猫」，柿红小围裙与偏圆轮廓；表情开心/焦急/小骄傲三种。首个版本不依赖整张复杂立绘动画，每个角色用分层头身、眼口和少量动作即可。
- **首页**：优先展示小院在阳光里呼吸，中央一个大按钮「开始晒晒」，四周只保留天气、今日宜晒、简洁导航，不用五颜六色九宫格。

### 5.4 图标风格（一套统一）

- 造型：软圆边、手刻木牌/糯米纸贴纸质感，顶部轻高光，底部短软阴影；线条色 `#6D695B`，线粗等效 2–3px@96px 基准。
- 主动作用具（摆、移、盖、收、压）视觉一组：竹匾、脚印、竹罩、屋门、鹅卵石；不能用五个样式不一致的 emoji 替代正式资源。
- 功能图标：天气、铜钱、星、图鉴、设置、音量、分享、帮助、回退；可辨性优先于装饰。
- 资产统一方形画布、透明边距约 8%；导出 PNG/WebP 以及可编辑母版（SVG/分层文件）。
- 应用图标 1024×1024 母版：屋檐 + 一匾橙金柿饼 + 一角太阳，纯图形无小字；缩小到64×64仍能辨认。名称商标待查，不把未核验名称直接写进图案。

### 5.5 UI 布局和交互标准

基准 `390×844` CSS px，支持 320–430 宽手机，充分处理 `safe-area-inset-*`，中档安卓测试；不要直接按设计稿绝对定位所有按钮。

```
│ 今日宜晒 · 节气     ⚙   │  6%  顶部信息
```

- 首屏只有 **1 个强调主按钮**（进入游戏 / 推进时辰），动作控件随需显示，不抢主场景。
- 触控最小有效区域 `44×44 CSS px`，常用按钮优先 48+；底部操作手指可及；可点区与美术透视格**单独建立隐形命中区域**。

- 雨警告不要大弹窗打断操作，天气带转为雨青 + 小雨娃提醒；非首关仅需短气泡。
- 动作按钮空态/加载态/成功态/失败态四态齐全；新手提示不遮挡下方被指引的交互目标。

### 5.6 动效与声音的精细程度

| 事件 | 动效 | 时长（起步） | 声音/触觉 |
|---|---|---:|---|
| 拖起竹匾 | 浮起6px+阴影增强 | 120ms | 竹编轻响 |
| 放置 | 软弹回落+两粒尘点 | 180ms | 咚/笃 |
| 干度增长 | 晒物色彩/弧度缓变、干度条涌动 | 350ms | 无或轻铃 |
| 达到绿区 | 金线扫过 + 小星粒 | 400ms | 清脆叮 |
| 收成 | 匾飞向屋檐收纳处，出现「刚刚好」印章 | 550ms | 连续上行音（原创） |
| 变天 | 云影扫过、屋檐雨线渐入 | 450ms | 风铃+细雨 |
| 霉变/丢失 | 可怜表情、短促摇摆；不做恐怖效果 | 260ms | 轻闷响 |
| 结算 | 各品依次翻牌+星级跃出 | 0.8–1.3s | 竹铃、铜钱轻碰 |

- 动画结束后才开放下一回合可重复触发，**所有过渡可跳过**，设置支持关动画/静音；低性能时减少粒子与景深，不降低操作反馈清晰度。
- 音乐由原创短循环或合规商用素材制作：轻木鱼节奏、竹笛点句、风铃与院落环境声；禁止使用未经授权的流行歌曲或他人游戏配乐。

## 6. 游戏架构与工程边界

### 6.1 原则

1. **逻辑内核/渲染/平台适配三层分离**：P1 浏览器 H5 只验证体验；微信小游戏必须另做平台渲染或使用经验证的引擎目标构建。
2. 规则函数 deterministic：同一 `seed + stage + actions + rulesVersion` 必有同一结果。
3. 数据驱动：晒物、小院、天气、关卡、黄历、商店、街坊均可独立配置，配 schema 校验。
4. **禁止**在组件点击事件中直接编造得分、霉点、天气；任何变化走 `dispatch(action)` 与纯 `reduce(state, action)`。
5. 原型支持离线运行，LocalStorage 存档加版本号；正式微信端迁移至 `wx.setStorage` 等适配层。敏感权限请求应延迟到用户需要时。
6. 没有真实广告 SDK 时，只能显示“模拟广告（不计收入）”；不能假称观看或完成广告。

### 6.3 状态对象建议

```
GameState = {
  schemaVersion, rulesVersion, mode, stageId, seed,
  turnIndex, weatherActual[], weatherForecast[], apRemaining,
  inventory: [{instanceId, itemId, dry, mold, location,
               cellId, covered, pressed, smellHit, lostReason}],
```

- `actionLog` 包含 `turnIndex`, `actionType`, `instanceId`, `fromCell`, `toCell`，不写用户隐私数据。

- 对每日挑战分数 **只允许从规则内核结果生成**；广告铜钱双倍单独计算。

### 6.4 正式微信适配（后期，不可假装已经完成）

- 优先评估 Cocos Creator 适用的小游戏构建流程，或原生 Canvas 渲染方案；不直接将含 DOM 的网页上传当作小游戏包。
- 需要逐项核实当前微信官方的：小游戏类目/主体要求、备案/版号/软著等适用规则、分包和资源限制、隐私规范、小游戏广告入口、SDK 生命周期、基础库版本。
- 激励视频以 `wx.createRewardedVideoAd` 类接口为候选，**接入时以微信官方最新文档为准**；先开通合规广告位，不使用虚构广告 ID。
- 浏览器适配层提供 `requestReward()` mock；微信适配层只有**确认完整观看且平台回调成功**才发奖，失败/关闭/广告不足均不发奖励且不阻断正常游戏。
- 好友榜开放数据域、排行榜防作弊、订阅消息均属 P3/P4，不把 H5 模拟等同已接通。

## 7. 商业化与公平性

### 7.1 首发候选点位（先验证再决定启用）

| 场景 | 获得 | 频次初始限制 | 影响积分榜？ |
|---|---|---|---|
| 普通关日落结算 | 额外获得本局同额铜钱（分数不变） | 每天至多2次 | 不影响 |
| 普通关容错 | 可撤销上一时辰并重选一次 | 每天至多2次 | 不计入同题竞赛 |

- **P1/P2 使用模拟广告 UI，并明确标注不是真广告。**
- 不做开局弹广告、不出现伪关闭按钮、不做错觉点击、不承诺“看了必过关”；重复广告应控制在玩家主动行为范围内。
- 如日后开放“预报更准/额外AP”，只限不计分单人娱乐关；**正式每日同题周榜不开放改变信息或动作预算的广告增益**。
- 广告可用性失败返回无广告状态，免费可继续正常游戏；有无广告体验差距不应破坏基本玩法。

### 7.2 不做收入预估承诺

真实收益取决于日活跃玩家、广告触发率、填充率、eCPM、平台条件以及合规运营，P1 不进行盈利预估。数据先看好玩与否，再看广告承受度；不能为了提高广告次数牺牲次留。
